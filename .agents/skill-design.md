# EV Service Center Agent Skill Design Document

This document outlines the design for a specialized agent skill (`ev-service-center-developer`) tailored for the EV Service Center Management project. 

## 1. Skill Overview
- **Name:** `ev-service-center-developer`
- **Description:** A specialized coding skill to assist AI agents in developing, debugging, refactoring, and maintaining the microservices architecture and Next.js frontend of the EV Service Center project.
- **Goal:** Ensure all agentic code contributions adhere to the established Microservices constraints, MVC patterns, Security rules, and API conventions outlined in the project analysis and standards.

## 2. Capability Guidelines

The skill will equip the agent with the following specific guidelines:

### 2.1 Creating New Features
- **Backend (Node.js/Express):** 
  - Standard workflow: Create Sequelize Model -> Define Controller -> Map Routes -> Attach Auth Middleware.
  - Mandate wrapping all controller logic in `try...catch` blocks.
  - Enforce role-based access control (`authorizeAdmin` middleware) for sensitive endpoints.
- **Frontend (Next.js 15):** 
  - Guidelines for creating UI components in `src/components/`, pages using App Router in `src/app/`, and wrapping API logic inside custom React hooks (`src/hooks/`).
  - Use `httpClient.ts` for all external data fetching to ensure interceptors and auth tokens are properly utilized.
- **Database:** Rules for creating strictly isolated models within a specific service's database. No cross-database relationships (foreign keys) are allowed at the DB level.
- **Inter-service Calls:** When a new feature requires data from another service, the skill will instruct the agent to build an Axios client in `src/client/` using the `INTERNAL_SERVICE_TOKEN` header.

### 2.2 Fixing Bugs
- **Tracing Errors:** Teach the agent to trace API Gateway routes (e.g., `/api/booking` -> port 5002) to locate the exact microservice and controller.
- **Authentication Issues:** Guidance on handling `401 Unauthorized` issues by checking the `Authorization` header format, `httpClient.ts` interceptors, and the state of `localStorage`.
- **Database Errors:** Standardizing debugging of Sequelize Validation errors.

### 2.3 Refactoring Code
- **Service Layer Migration (Primary Refactoring Goal):** Since current business logic is tightly coupled inside Controllers, the skill will include a specific playbook for migrating complex logic into a dedicated `src/services/` layer, leaving the Controller to handle only HTTP Request/Response mapping.
- **Repository Pattern Intro:** Guidelines on extracting direct Sequelize calls (`Model.findAll()`) from controllers into a repository layer to improve testability.

### 2.4 Writing Tests
- **Setup Testing Framework:** Since no tests currently exist, the skill will guide the agent to scaffold a testing environment (e.g., Jest and Supertest for Backend, React Testing Library for Frontend).
- **Unit Testing Guidelines:** Instructions on mocking Sequelize models and inter-service HTTP clients (`src/client/`) using libraries like `jest.mock` or `nock` to ensure isolated testing.
- **Integration Testing:** Guidelines on testing the Gateway routing and Auth flow.

### 2.5 Following Architecture
- **Strict DB Isolation:** Emphasize the "Database-per-Service" rule.
- **Naming Conventions:** Reinforce camelCase for variables/functions, PascalCase for Models/React Components, kebab-case for service folders, and UPPER_SNAKE_CASE for environment variables.
- **API Formatting:** Ensure paginated responses always return the standard envelope: `{ data, total, page, limit, totalPages, hasNext, hasPrev }`.

## 3. Skill File Structure (`SKILL.md`)

The final skill will be defined in a `SKILL.md` file containing the following sections:

1. **Frontmatter:** YAML metadata (name, description).
2. **Context:** Brief overview of the EV Service Center microservices layout.
3. **Core Rules (Anti-patterns to Avoid):**
   - *DO NOT* query another service's database directly.
   - *DO NOT* skip `try...catch` blocks in controllers.
   - *DO NOT* create write-APIs without authentication.
4. **Playbooks (Step-by-Step Instructions):**
   - `[Playbook 1: Creating a New Microservice API]`
   - `[Playbook 2: Frontend Data Fetching]`
   - `[Playbook 3: Refactoring Controller to Service Layer]`
   - `[Playbook 4: Writing a Backend Unit Test]`
5. **Reference Definitions:** Quick links or snippets of standard code (e.g., standard error response, standard pagination response).

## 4. Next Steps
Once this design is approved, the `ev-service-center-developer` skill can be generated by creating the `SKILL.md` file and (optionally) providing template snippets in a `templates/` subdirectory to accelerate future development tasks.
